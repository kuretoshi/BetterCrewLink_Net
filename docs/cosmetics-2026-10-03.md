# コスメティック移植の進捗

基準: v3.2.7 `9861ccc8137bb63a7d3834f493be0b784a288544` の `renderer/lib/cosmetics.ts` と `components/Avatar.tsx`。

`CosmeticCatalog` に共有hats.jsonの読取・画像選択を移植した。IDは大文字小文字を区別し、NONE定義をMOD定義より優先する。前／後画像、項目固有の配置とグループ既定値、multi_colorフラグ、%/px配置値を扱う。カタログ由来のURLは既存配信元の対応グループ内に制限する。

検証:

- Releaseビルド、`--cosmetics-self-test` は終了0。IDの大文字小文字、NONE優先、MODフォールバック、後画像、欠落画像、不正相対パス、配置値を検証。
- `--cosmetics-self-test --download-cosmetics-catalog` は実際の3.2.7と同じ配信元からカタログを取得し、5グループ・3421件の前後画像指定を解決した。全解決画像の配置値もパースできた。画像ファイル自体の全件ダウンロードや描画検証ではない。

このコミットは画像選択の基盤であり、コスメティック表示完了ではない。次に画像の非同期読込、体色連動、前後関係、死亡時非表示、アバタークリップとオーバーフロー、変装・追加帽子を接続する。SNRのリモート定義／ローカル画像と固有配置も別途必要。起動中の.NET画面にはこの基盤をまだ接続していない。

## 共有カタログ描画への接続

非同期画像読込とフリーズしたWPF画像キャッシュを追加し、PlayerAvatarへ帽子後面→体→服→帽子前面→バイザーの順で接続した。体と服は円形クリップ、帽子・バイザーは外側へはみ出せる。体を上22%・幅105%・左−7pxへ配置し、装備はカタログ配置値と3.2.7の境界補正を用いる。死亡時は装備を非表示にし、変装中はappearance IDを選択する。adaptive画像は既存の3.2.7マスク色変換を使用する。

画像取得の世代番号を持ち、装備変更やコントロール破棄後の古い応答を適用しない。カタログ失敗は30秒後に再試行可能とし、画像失敗はそのレイヤーだけを表示しない。メインとオーバーレイの呼出元からMOD識別を渡す。

`--cosmetics-self-test` にWPFレイヤー数・帽子／バイザー順・80pxアバターの配置・体クリップ・死亡時消去・古い非同期応答破棄を追加した。ビルド（警告/エラー0）と名前・NoS色・オーバーレイテストも成功。

この時点では実画像の描画比較や実機更新は行っていない。SNRのリモート／ローカルコスメティック、追加帽子／追加バイザー、NoS公開色に対応する色IDのadaptive画像への反映などが残る。共有カタログを使う描画経路の実装であり、全コスメティック対応完了ではない。

## NoSのadaptive装備色

3.2.7 `common/NosSnapshot.ts` の `findNosColorIndex` と `Avatar.tsx` に合わせ、NoS公開スナップショットRGBをバイト丸めした後、各成分差が1以内の**最初**のパレット色を使用する。最近傍探索ではない。該当色がなければ変装色（outfit 1〜10かつ有効色ID）、次に通常色へフォールバック。ロビー専用RGBは体画像用であり、この装備色検索には用いない。他MODではNoS値を参照しない。体画像のNoS分岐もMOD識別で制限した。

Releaseビルドは警告/エラー0。`--nos-avatar-self-test --cosmetics-self-test --overlay-self-test --voice-view-self-test` は終了0。許容差・先頭優先・MOD分離・不正RGB・変装範囲・ロビーのみのフォールバックと、SetPlayerからadaptive画像への実ピクセル変換、公開色変更後の再着色を確認した。これらは合成マスクによる自動テストであり、ゲーム内でadaptive装備を着替えて公式と比較する実機確認は未実施。起動中の配布フォルダは前のコミットのまま。

## SNRリモート装備

3.2.7 `renderer/lib/cosmetics.ts` のSNR公開定義読込とID解決を移植。タグ除去後のpackage/name完全一致を優先し、その後に画像名の連続suffix除去・英数字正規化・末尾一致を使う。前後画像は別に選択し、adaptiveフラグまたは各画像名のadaptive表記で着色する。バイザー以外の種別は原版同様に帽子定義を参照する。

フルキャンバス既定配置と、IsSNR/isSNRの原版と同じ型条件を適用した自然画像サイズによるバイザー配置を接続。共有カタログに同じIDがある場合は画像指定の有無にかかわらずそちらの配置を優先する。共通画像キャッシュ、世代番号による古い応答の破棄、失敗時再試行経路を利用する。

Releaseビルド警告/エラー0。`--cosmetics-self-test --download-cosmetics-catalog --nos-avatar-self-test --overlay-self-test --voice-view-self-test` は終了0。SNR ID・suffix・前後選択・adaptive条件・小／大キャンバスの配置、PlayerAvatarまでの描画接続を合成画像で検証。実配信元から帽子388定義・バイザー48定義を取得し、それぞれ先頭の画像1件（300×375、397×88）を取得してデコードできた。全画像取得やSNR実機との見た目比較は未実施。

未対応のローカルfallback（SuperNewRolesNext/CustomCosmetics）、追加帽子／バイザーと読取、SNR実機の比較は引き続き必要。定義にないModded_装備は現時点では非表示。起動中のアプリは更新していない。

## SNRローカルフォールバックの接続

上記の未対応項目のうちローカル画像解決を実装。読み取り対象のゲーム実行ファイルパスを状態→メイン／オーバーレイ→アバターへ渡す（JSONでは除外）。そのゲームの `SuperNewRolesNext/CustomCosmetics` のみで、package名・タグ除去・3.2.7のファイル名サニタイズ・種別ごとのsuffix順・bundle除外を適用する。Multiverse Costume SELの帽子前後だけをadaptive扱いにする。

リモート定義で解決できない場合はローカル画像へフォールバック。SNR定義の通信エラーもローカル経路を遮断しない。なお原版同様、リモートURLが解決できたがその画像ダウンロードが失敗した場合はローカルへ切り替えない。共通カタログ自体の取得は現時点で従来どおり前提となる。

ローカルPNGも画像キャッシュで非同期読込・Freezeする。ゲームパスを装備キーに含め、再試行待ちは同じ装備キーにだけ適用するよう修正した。別ゲーム・別装備へ切り替わった場合は待たずに古いレイヤーを消去する。

Releaseビルド警告/エラー0、コスメティック・NoS色・名前・オーバーレイ自動テスト終了0。専用一時フォルダーに生成したPNGでsuffix順、タグ、root分離、adaptive対象、実PNGデコードを検証し、通信失敗を注入したPlayerAvatarでもローカル帽子前後とバイザーが描画されること、別ゲームへの切替で消去されることを検証。一時テストデータはテスト終了時に削除し、ユーザーのゲームデータには変更していない。

実際のSNRゲームフォルダーからの装備表示・公式画面比較は未検証。追加帽子／バイザーと読取も引き続き未対応。起動中のアプリは更新していない。
