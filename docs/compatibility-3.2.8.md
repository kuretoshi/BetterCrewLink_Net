# TanukiBCL v3.2.8 compatibility checkpoint

Target: released [`v3.2.8`](https://github.com/kuretoshi/TanukiBCL/releases/tag/v3.2.8), commit `8d52d02beee8410e0c4dfa06f704c7a41f5fe962`. The .NET port is **not yet fully compatible**. The user-approved game scope is 64-bit Among Us only.

## Newly ported from 3.2.8

- The NoS `TbclSnapshotReader` source matches the released upstream file byte-for-byte. It resolves `nextIndex`/`Latest` and reads snapshots without writing `RequireUpdate` or requesting game-process write access. Only the `win-x64` helper is built and bundled.
- The .NET NoS snapshot and dynamic-palette readers now decode 64-bit pointers and 64-bit array headers, including addresses above 4 GiB. A 32-bit snapshot is explicitly rejected as unsupported.
- Process pickers and the game scanner exclude terminated Among Us processes with zero threads, corresponding to the new upstream process filter.
- The compact-view footer includes the new Ko-fi and X buttons and their released URLs.
- Localization assets and settings/window localization work from the earlier 3.2.7 port are included in the same working set; this is partial GUI parity, not a claim of completion.
- The settings navigation now uses the same nine Material icon paths, purple selected-row tint, and category ordering as the released renderer. The General page now places language and reset actions in separate cards; the always-on-top control is only on the Overlay page, where the released settings place it. The settings localization and live-save self-test pass after that control move. This is a source-guided alignment, not a verified whole-window visual match.
- The Overlay settings page now follows the released `OverlaySection` card: four right-aligned switches, row separators, and an avatar-position selector in the final row. The disabled state of compact, meeting, and position controls still follows the overlay-enable switch. Release build and settings localization/live-save tests pass; rendered 3.2.8 visual parity is not yet verified.
- The running released 3.2.8 settings renderer was visually compared with the .NET settings window. The .NET window now uses a 24 px dark draggable title bar with settings icon, localized title, minimize and close buttons, matching the upstream frameless window dimensions and minimum size. Its permanent save-status footer is gone; save/reset failures still surface in a temporary error banner. Release build, localization self-test, and visible WPF rendering passed. Individual category contents and pixel-level parity remain to be audited.
- The released 3.2.8 game-waiting screen was inspected live. The .NET compact view now shows the localized waiting title, animated spinner, `プリセット` label, split launch button, and a dark drop-down of available launch targets plus custom-target creation instead of permanently visible edit controls. The player-list scroll layer is hidden while waiting so it cannot intercept launcher clicks. Selecting Epic Games and restoring Steam worked in the live .NET window; the custom-target dialog opened and was cancelled without changes. The selected target button grows for longer names. Release build and launcher self-tests pass; the title bar and remaining menu details are not yet pixel-identical to 3.2.8.
- The released 3.2.8 Audio settings page was compared with the .NET Release window. The .NET page now groups microphone/speaker devices, voice mode, microphone gain/sensitivity, playback volumes, and voice-effect test into corresponding cards and separators. The device selectors use a readable dark control and drop-down; opening and cancelling the microphone selector was checked live without changing devices. The existing live setting/save and preview hooks remain on the same controls; Release build and settings self-tests pass. Pixel-level control styling and real audio-device switching remain unverified.

The merge preserves peer-specific measurements. Release build and `--voice-view-self-test` pass.
- The WPF peer indicator now receives actual per-peer inbound jitter and interval packet loss: jitter is estimated from received Opus RTP timestamps and monotonic arrival times, while loss uses the fraction in our outgoing RTCP reception report. A live two-peer `--quality-self-test` passed with 3.6 ms jitter and 0.0% loss, and synthetic tests cover RTP timestamp wrap, source reset, and RTCP loss conversion. The library's raw RTCP jitter value was rejected after it reported an implausible 185,955.6 ms during a healthy local audio test. The nominated ICE candidate pair supplies the upstream-equivalent direct-path flag. Synthetic host/relay/no-pair tests and a second live two-peer `--quality-self-test` passed with `direct=True` on a local host pair, 2.2 ms jitter, and 0.0% loss. Per-peer RTT now uses RFC 3550 RTCP sender/reception report round trips, matching SSRC and last-sender-report timestamp and subtracting the remote reporting delay; unrelated, missing, implausible, or stale samples are ignored. A further live two-peer test returned `rtt=1.2 ms`. Upstream 3.2.8 instead uses the selected ICE candidate pair's RTT, so metric equivalence and the live official 3.2.8 GUI quality comparison are still outstanding.
