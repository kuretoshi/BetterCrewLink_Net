# v3.2.7 voice-disguise checkpoint (2026-10-02)

The .NET receive path now selects the released `voiceEffectRules.ts` generic disguise effect when a live task-phase speaker's appearance name differs from their base name. NoS size effects remain higher priority. The lobby switch and listener-local 0–100% strength setting are exposed in WPF, with the released default of 100%. The receive filter and dry/wet gains follow `voiceEffect.ts`, using its 35 ms pitch-up delay topology. The Web Audio bandpass Q is linear; low/high-pass Q uses different units ([Web Audio specification, section 1.13](https://www.w3.org/TR/webaudio/#BiquadFilterNode)).

Synthetic policy tests cover the changed-name condition, zero strength, lobby disable, impostor radio, dead listeners, NoS size priority, and the NoS zero-height fallthrough guard. A synthetic center-band tone test confirms the pitch-up component. The Release and Debug client builds have zero warnings, and the WPF smoke test constructs the settings dialog and checks its new controls. The rebuilt Debug client was restarted on Among Us PID 60232 and displayed the four-player lobby. The Windows UI helper failed to capture the settings dialog (`foreground window did not report a process id`) even after recovery, so manual settings interaction and an actual shapeshift listening comparison remain unverified. The client was restarted again to leave it out of the modal dialog.

Two other vDEV clients' visible Reload controls were clicked. One client with NAT fix ON was temporarily switched OFF at the user's request; its peer indicators remained good. NAT fix was then restored to ON, including the app's confirmation dialog, and visually verified. This short UI-only comparison cannot establish actual Opus quality or determine whether NAT fix caused a connection failure.

Remaining voice-effect parity gaps include the SNR Jumbo and Jackal role data paths, the Airship meeting-by-outfit fallback, and the upstream test-effect button. This is not a compatibility-complete checkpoint.
