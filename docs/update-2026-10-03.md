# .NET版アップデート経路の準備

追記: 更新ZIPの検証・展開後に設定画面が閉じられた場合や更新補助ツールへの引き渡しに失敗した場合、未使用の一時展開ディレクトリを削除する。ビルド（警告0）と更新カタログ・ZIP検証の自己テストを再実行した。実際の公開Release経由更新は未検証。

公式3.2.7の `UpdateSection.tsx` と `src/main/index.ts` を確認。表示状態は idle/checking/unavailable/available/downloading/downloaded/error、開始操作後にElectron用NSIS更新物を取得して終了・更新する。公式の更新先を.NET版にそのまま向けると別製品のElectronアプリが導入されるため、.NET版の配布元は `kuretoshi/BetterCrewLink_Net` とする。

現時点で同リポジトリのGitHub Releaseは0件（`gh release list`で確認）。`UpdateCatalog` は将来の `.NET` 配布物 `TanukiBCL.Net-win-x64.zip` のみを対象にする。Release一覧から現在バージョンより新しいものを選び、GitHubの所定の配布URL、アップロード完了状態、正のサイズ、64桁のSHA-256 digestを必須とする。[GitHub REST APIのReleaseアセット](https://docs.github.com/en/rest/releases/releases)にはこのdigestフィールドが定義されている。偽HTTP応答で新旧バージョン、無効digest、404を検証した。Releaseビルド0警告/0エラー、`--update-catalog-self-test`終了0。

後続実装で、設定画面に9番目の「アップデート」カテゴリを追加した。確認→候補あり/なし/エラー→開始→ダウンロード進捗→終了・更新の操作経路を接続した。候補がない時や更新補助ツールのない開発起動では開始を無効化する。ZIP取得は公開サイズとSHA-256を照合し、パス逸脱・重複・Windows予約名・シンボリックリンク・過大展開を拒否してから一時領域に展開する。`TanukiBCL.Updater`は本体終了を待ってから新旧ディレクトリを入れ替え、旧版を別ディレクトリに保持する。起動失敗時には旧版へ戻す。設定画面と更新補助ツールを配布物へ同梱した。

`tools/package-release.ps1 -Version 3.2.7-netdev.0`でself-contained win-x64配布ZIPを作成した。最初の試行ではPowerShell標準圧縮がZIP内にWindowsの`\`区切りを記録し、安全検査で拒否されたため、スクリプトからZIPエントリ名を`/`で明示する方式に修正した。最終のローカル配布物は `dist/3.2.7-netdev.0/TanukiBCL.Net-win-x64.zip`、163,499,891 bytes、SHA-256 `2b394486cbb4eff7dc869df211481de027129b58dfd734e3b2641ff53c08ea35`。このZIPを同梱済みアプリ自身の更新ステージング処理に通し、検証・展開・必須ファイル確認が終了0。更新補助ツールのテストでは入れ替え、旧版保持、起動失敗時の巻き戻しが終了0。配布物の設定・オーバーレイ・音声入力処理などの自己テストも終了0。

GitHub Releaseはまだ作成していない。したがって設定画面から公開Releaseを確認・ダウンロードして実行中アプリを入れ替える一連の実機検証、新規Windows環境での起動・更新検証は未実施。起動中の.NET版は旧パッケージで、Windowsネットワーク許可待ち。失敗した最初の2つのローカル配布試行と再生成前の配布物は `dist/failed-3.2.7-netdev.0*`、`dist/pre-final-3.2.7-netdev.0` に保存しており、正常な配布ZIPには含まれない。
